# Untangle MVP 구현 지시서

## 0. 한 줄 요약

흩어진 AI 대화 기록을 붙여넣으면 프로젝트 대시보드가 만들어지고, 사용자가 요청하지 않아도 "오늘 해볼 만한 한 걸음"을 초안과 함께 먼저 건네는 웹 앱. 제출 기한은 2026-11-15.

## 1. 함께 주는 파일

| 파일 | 내용 | 다루는 법 |
|---|---|---|
| `onboarding_prompts.md` | 내보내기 프롬프트, 온보딩 처리 흐름, 겹침 찾기 호출, 대체 병합 프롬프트, 앱이 관리하는 값 | 명세. 그대로 따른다 |
| `parse_export.js` | 내보내기 결과 파서 + 사전 분류 참고 구현 | TypeScript로 옮긴다. 분류 규칙과 마감 처리 규칙은 바꾸지 않는다 |
| `topic_schema.json` | 토픽 데이터 형식 | 타입 정의의 기준 |
| `nudge_prompt.md` | 제안 카드 생성 프롬프트, 입력 형식, 앱이 맡는 일 | 명세. 프롬프트 문구는 임의로 고치지 않는다 |
| `nudge_schema.json` | 제안 카드 출력 형식 | 구조화 출력에 사용 |
| `tokens.css` (나중에 제공) | 디자인 토큰 | 5단계 전까지는 임시 값으로 둔다 |

명세와 이 문서가 어긋나면 작업을 멈추고 물어본다.

## 2. 기술 선택

- Next.js (App Router) + TypeScript + Tailwind CSS
- 저장: 브라우저 localStorage만. 로그인, DB, 서버 저장 없음
- LLM 호출: 서버 Route Handler에서만. API 키는 환경 변수로 두고 브라우저에 노출하지 않는다
- LLM 연결은 `lib/llm.ts`의 함수 하나로 감싼다: `generateJSON({ system, user, schema }) → object`. 공급자를 바꿔도 이 파일만 고치면 되게 한다
- 배포: Vercel
- 테스트: Vitest. 파서, 분류, 응답 검증은 단위 테스트 필수

## 3. 만들지 않는 것

- 로그인, 결제, 여러 사용자, 서버 DB
- 웹 검색, 논문·뉴스 인용
- ChatGPT·Claude 계정 연동, 채팅 자동 수집, 파일 시스템 접근
- 코딩 에이전트 실행(터미널, git)
- 토픽을 열 때마다 하는 LLM 호출
- 모바일 전용 화면 (데스크톱 폭 1280px 기준. 좁은 화면에서 깨지지만 않으면 된다)

## 4. 화면

### 4.1 온보딩 (`/start`)

1. **프롬프트 복사**: 내보내기 프롬프트(명세 ①)를 보여주고 복사 버튼. "ChatGPT나 Claude에 붙여넣고 답을 복사해 오세요", "결과가 끊기면 '계속'이라고 입력하세요" 안내.
2. **붙여넣기**: 출처 선택(ChatGPT / Claude / 기타) + 텍스트 칸. "다른 AI 결과 추가"로 여러 개. "샘플로 둘러보기" 버튼(6단계).
3. **확인**: 세 묶음(활성 제안 / 나중에 제안 / 정리 제안). 토픽마다 이름, 테마 꼬리표, 분류 까닭. 토픽별 이동 버튼, 묶음별 "전부 나중에"·"전부 삭제", 맨 아래 "이대로 시작".

처리 순서는 `onboarding_prompts.md` ②를 따른다. 출처가 하나면 LLM 호출 없이 확인 화면까지 간다.

### 4.2 대시보드 (`/`)

토픽이 없으면 `/start`로 보낸다.

- **왼쪽 (토픽)**: 맨 위에 별 토픽과 따로 뺀 토픽 → 테마별 구역(접기 가능, 활성 수 표시) → 접힌 "나중에" 구역. 토픽 항목에 이름, 마감까지 남은 날(있을 때), 출처 표시. 별은 최대 3개. 토픽 메뉴: 별, 나중에/다시 활성, 테마 옮기기, 따로 빼기, 삭제.
- **가운데 (제안)**: "지금 이어가기" 카드 최대 2장, "이런 것도 있어요" 카드 최대 1장, 수락한 "진행 중" 카드. 위쪽에 "새 제안 받기" 버튼.
- **오른쪽 (상세 패널)**: 카드를 누르면 열린다. 초안(head_start)을 그 자리에서 고칠 수 있는 편집 칸, 질문 카드면 선택지 버튼, 근거(evidence) 목록, 버튼들.

토픽을 누르면 가운데가 그 토픽 보기로 바뀐다: 목표, 현재 상태, 지금까지 만든 것, 최근 결정, 막힌 점, 다음 할 일, 관련 대화 주제, 출처, 그리고 그 토픽의 카드. 이때 LLM을 호출하지 않는다.

### 4.3 카드 버튼

| 버튼 | 동작 |
|---|---|
| 해볼게요 (수락) | 카드를 "진행 중"으로. new_project면 이때 토픽 생성 |
| 다 했어요 (완료) | 한 줄 메모(선택)를 받고 completed 기록. 카드 사라짐 |
| 나중에 | 다음 날까지 숨김. 저장된 카드를 그대로 다시 보여줌 |
| 관심 없어요 | dismissed 기록. 카드 사라짐 |
| Claude에서 이어가기 / ChatGPT에서 이어가기 | 아래 넘기기 문구를 클립보드에 복사하고 새 탭으로 해당 서비스를 연다 |

질문 카드에서 선택지를 누르면 그 답을 토픽의 메모에 저장하고 카드를 completed로 기록한다(note에 선택한 답).

넘기기 문구(코드로 조립, LLM 호출 없음):

```
[프로젝트] {토픽 이름}: {한 줄 설명}
[지금 상태] {status_text}
[하려는 일] {카드 title}: {카드 action}
[준비된 초안]
{사용자가 고친 head_start 내용}

이 초안에서 이어서 도와줘.
```

### 4.4 상태 화면

- 카드 생성 중: 카드 자리에 뼈대(skeleton)와 "초안을 준비하고 있어요"
- 카드 0장: "오늘은 새로 권할 게 없어요. 진행 중인 일을 이어가 보세요" + "새 제안 받기"
- LLM 실패: 카드 자리에 짧은 오류 문구와 "다시 시도". 대시보드의 다른 부분은 그대로 동작
- 파싱 실패: 붙여넣기 칸 아래에 "형식을 읽지 못했어요. AI로 정리해 볼까요?" 버튼(대체 경로 호출)

## 5. 서버 경로

| 경로 | 쓰임 | 명세 |
|---|---|---|
| `POST /api/cards` | 제안 카드 생성 | `nudge_prompt.md` |
| `POST /api/dedupe` | 여러 출처의 겹침 찾기 | `onboarding_prompts.md` ③ |
| `POST /api/merge` | 파싱 실패 시 대체 병합 | `onboarding_prompts.md` ④ |

- 입력 크기 상한을 둔다(붙여넣기 합계 200KB, 토픽 9개). 넘으면 400.
- 응답은 스키마로 검증하고, `nudge_prompt.md` ③의 검증 규칙을 적용한 뒤 내려준다.
- 간단한 호출 횟수 제한(IP당 분당 10회)을 둔다. 공개 배포에서 키가 소진되지 않게.
- 서버에 사용자 데이터를 저장하거나 로그로 남기지 않는다.

## 6. 작업 순서와 완료 기준

각 단계가 끝나면 멈추고 결과를 보고한다. 다음 단계는 확인 후 시작한다.

### 0단계: 카드 품질 확인 스크립트 (앱보다 먼저)

- `scripts/try-cards.ts`: 가상 페르소나 2명의 입력(`samples/`)으로 실제 API를 각 5회 호출하고 결과를 `out/`에 저장.
- 가상 페르소나는 직접 지어낸다: (a) 대형 게임사 개발자, (b) 팀플과 개인 프로젝트를 병행하는 대학생. 각각 내보내기 형식의 텍스트로 만들고 파서를 거쳐 입력을 만든다.
- 스키마가 API에서 거부되면 거부된 키워드를 보고한다. 임의로 스키마를 바꾸지 않는다.
- 완료 기준: 10회 결과 파일과, 스키마 통과 여부·카드 수·explore 카드 수를 정리한 표.

### 1단계: 프로젝트 뼈대와 파서

- 프로젝트 생성, `lib/llm.ts`, 타입 정의.
- `parse_export.js`를 `lib/parse.ts`로 옮기고 단위 테스트.
- 완료 기준: 가상 페르소나 2개 + 깨진 입력 3종(빈 텍스트, 칸 이름이 다른 텍스트, 테마 없는 텍스트)에 대한 테스트 통과. 원본 JS와 같은 입력에서 같은 출력.

### 2단계: 온보딩

- 4.1의 세 화면, localStorage 저장, 삭제 이름 목록.
- 완료 기준: 가상 페르소나 텍스트를 붙여넣어 확인 화면까지 LLM 호출 없이 도달. 묶음 이동과 "이대로 시작" 후 새로고침해도 유지.

### 3단계: 대시보드의 토픽 영역

- 4.2 왼쪽과 토픽 보기. 별(최대 3), 나중에, 삭제, 테마 옮기기, 따로 빼기, 테마 접기.
- 완료 기준: 모든 조작이 새로고침 후에도 유지. 삭제한 토픽은 같은 텍스트를 다시 붙여넣어도 나타나지 않음.

### 4단계: 제안 카드

- `/api/cards`, 홈 카드, 상세 패널, 4.3의 버튼, 4.4의 상태 화면, 생성 시점 규칙.
- 완료 기준:
  - 온보딩 직후 카드가 자동으로 나타난다
  - "관심 없어요" 후 "새 제안 받기"를 누르면 그 방향의 카드가 다시 나오지 않는다
  - 수락한 카드는 "진행 중"으로 남고 그 토픽에는 새 카드가 생기지 않는다
  - 같은 날 새로고침해도 LLM을 다시 호출하지 않는다
  - 넘기기 버튼이 고친 초안을 포함한 문구를 복사한다

### 5단계: 디자인 적용

- 제공된 `tokens.css`와 시안에 맞춰 화면을 다듬는다. 컴포넌트 안에 색·간격 값을 직접 쓰지 않고 토큰만 쓴다.
- `/kit` 페이지에 버튼, 칩, 토픽 항목, 카드(각 type), 상세 패널, 빈 상태, 뼈대를 모두 늘어놓는다.
- 완료 기준: `/kit`과 세 화면의 스크린샷.

### 6단계: 샘플 모드와 배포

- "샘플로 둘러보기": 가상 페르소나의 토픽과 미리 생성해 둔 카드를 불러온다. LLM 호출 없이 동작.
- 여러 출처 겹침(`/api/dedupe`)과 대체 병합(`/api/merge`) 연결.
- Vercel 배포, README(문제, 해결 방식, 실행 방법, 한계).
- 완료 기준: 배포 주소에서 샘플 모드 전체 흐름과 실제 붙여넣기 흐름이 모두 동작.

시간이 모자라면 6단계의 `/api/dedupe`, `/api/merge`를 먼저 뺀다. 0~4단계와 샘플 모드는 빼지 않는다.

## 7. 지킬 것

- 저장소에 실제 사용자의 내보내기 결과를 넣지 않는다. 샘플은 지어낸 페르소나만 쓴다.
- API 키를 코드나 커밋에 넣지 않는다. `.env.local`과 `.env.example`을 쓴다.
- 프롬프트 문구, 분류 규칙, 스키마는 임의로 바꾸지 않는다. 바꿔야 할 이유가 있으면 이유와 함께 제안한다.
- 사용자를 재촉하거나 평가하는 문구를 화면에 쓰지 않는다. 지난 마감을 빨간색으로 강조하지 않는다.
- 화면 문구는 한국어 존댓말, 짧게.
- 각 단계 끝에 보고할 것: 한 일, 실행한 테스트와 결과, 명세와 달라진 점, 확인이 필요한 질문.
