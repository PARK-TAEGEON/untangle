## 테마: 라이브 게임

### 협동 던전 첫 전투 안내
- 한 줄 설명: 가상의 협동 액션 게임에서 첫 전투의 역할 분담을 짧게 알려주는 튜토리얼을 만든다.
- 종류: 일
- 진행 여부: 진행 중
- 마지막으로 다룬 시기: 최근 2주
- 목표: 처음 플레이하는 두 사람이 3분짜리 전투에서 방어와 지원 신호를 한 번씩 알아보도록 안내 흐름을 완성한다.
- 현재 상태: 전투 시작과 방어 신호 안내는 연결했다. 지원 신호를 보여줄 시점과 테스트 기록 양식을 아직 정하지 않았다.
- 지금까지 만든 것:
  1. 전투 시작, 방어 신호, 지원 신호의 3단계 흐름 문서
  2. 방어 신호 안내가 동작하는 테스트 맵
  3. 관찰 항목 후보: 안내를 본 시점, 첫 방어 입력, 첫 지원 입력
- 최근에 내린 결정:
  1. 동시에 안내를 두 개 띄우지 않는다.
  2. 방어 신호 안내가 닫힌 뒤에만 지원 신호를 보여준다.
- 막힌 점이나 미정인 것: 지원 신호를 첫 피격 뒤에 보여줄지 방어 성공 뒤에 보여줄지 정하지 않았다. 테스트 전에는 어느 쪽이 더 좋은지 단정하지 않기로 했다.
- 마감·일정: 2026-11-13 (팀 내부 시연), 2026-11-20 (관찰 결과 공유)
- 내가 말했던 다음 할 일:
  1. 두 가지 지원 신호 시점의 차이를 비교하는 관찰표를 정리한다.
  2. 내부 시연에서 확인할 안내 문구 세 개를 짧게 고친다.
  3. 테스트 맵에서 안내가 겹치는 경우를 확인한다.
- 함께하는 사람: 게임 기획자, QA 담당자
- 관련 대화 주제: 협동 튜토리얼, 상태 전이, 관찰표, 안내 문구

### 이동 중 상호작용 오류 재현
- 한 줄 설명: 이동 도중 상자를 열면 상호작용 안내가 남는 가상 게임의 오류를 재현하고 수정 범위를 좁힌다.
- 종류: 일
- 진행 여부: 진행 중
- 마지막으로 다룬 시기: 최근 2주
- 목표: 오류가 발생하는 입력 순서를 재현 문서로 고정하고 안내 상태가 종료되는 조건을 확인한다.
- 현재 상태: 걷기 중 상자 열기에서는 3회 중 2회 안내가 남았다. 정지 상태에서는 3회 모두 안내가 사라졌다.
- 지금까지 만든 것:
  1. 걷기와 정지 상태를 비교한 수동 재현 기록
  2. 상호작용 시작과 종료 이벤트를 출력하는 임시 로그
- 최근에 내린 결정:
  1. 애니메이션을 바꾸기 전에 이벤트 순서를 먼저 비교한다.
  2. 재현 문서는 입력, 관찰 결과, 기대 결과 세 칸으로 쓴다.
- 막힌 점이나 미정인 것: 달리기 상태의 재현 여부는 아직 확인하지 않았다. 로그에서 종료 이벤트가 누락되는지 안내 위젯만 남는지 구분이 필요하다.
- 마감·일정: 2026년 11월 19일 (수정 범위 검토)
- 내가 말했던 다음 할 일:
  1. 기존 걷기와 정지 기록을 재현 문서의 세 칸에 옮긴다.
  2. 달리기 상태를 같은 입력 순서로 세 번 확인한다.
  3. 상호작용 종료 로그와 위젯 종료 로그를 한 줄씩 비교한다.
- 함께하는 사람: QA 담당자
- 관련 대화 주제: 오류 재현, 이벤트 순서, 상태 관리

### 플레이 로그 분류기
- 한 줄 설명: 테스트 로그를 전투, 이동, 상호작용으로 나누고 미분류 줄을 따로 남기는 사내 도구를 만든다.
- 종류: 일
- 진행 여부: 진행 중
- 마지막으로 다룬 시기: 최근 2주
- 목표: 가상의 테스트 로그 한 파일을 읽어 세 범주의 건수와 미분류 줄 목록을 출력하는 명령행 도구를 완성한다.
- 현재 상태: 전투와 이동 접두어를 읽는 Python 코드가 있다. 상호작용 접두어 두 종류는 아직 규칙 표에만 있다.
- 지금까지 만든 것:
  1. 접두어 규칙 표: Combat은 전투, Move는 이동, Interact와 Use는 상호작용
  2. 전투와 이동만 세는 명령행 코드
  3. 직접 지어낸 12줄짜리 테스트 로그
- 최근에 내린 결정:
  1. 알 수 없는 접두어를 버리지 않고 미분류로 남긴다.
  2. 결과에는 원본 줄 번호를 보존한다.
- 막힌 점이나 미정인 것: 빈 줄을 건수에서 제외할지 미분류로 포함할지 결정하지 않았다. 실제 업무 로그는 외부 샘플이나 공개 자료에 넣지 않는다.
- 마감·일정: 다음 주 도구 공유 시간
- 내가 말했던 다음 할 일:
  1. 상호작용 접두어 두 종류를 포함한 기대 출력 표를 만든다.
  2. 빈 줄 처리 방식을 정한다.
  3. 미분류 줄에 줄 번호를 붙이는 출력을 추가한다.
- 함께하는 사람: 도구 사용자 역할의 동료 개발자
- 관련 대화 주제: 로그 파싱, 명령행 출력, 회귀 사례

- 한 줄 설명: 두 사람이 서로 다른 단서를 보고 문 하나를 여는 작은 개인 게임을 만든다.

- 목표: 설명 없이 시작해 5분 안에 끝나는 방 하나를 친구 두 명이 플레이할 수 있게 만든다.
- 현재 상태: 문과 두 개의 스위치가 있는 회색 상자 맵이 있다. 각 플레이어가 볼 단서 문구는 초안만 있다.
- 지금까지 만든 것:
  1. 스위치 두 개와 문 하나가 연결된 프로토타입
  2. 단서 초안: 한 사람은 기호 순서를 보고 다른 사람은 기호와 스위치의 대응을 본다.
- 최근에 내린 결정:
  1. 음성 채팅이나 계정 기능은 만들지 않는다.
  2. 퍼즐은 기호 세 개의 순서를 전달하는 것 하나로 제한한다.
- 막힌 점이나 미정인 것: 순서가 틀렸을 때 처음부터 되돌릴지 마지막 입력만 취소할지 정하지 않았다.

  2. 잘못 입력했을 때의 두 가지 피드백을 비교한다.
  3. 테스트에서 지켜볼 관찰 항목 세 개를 적는다.
- 함께하는 사람: 테스트에 참여할 친구
