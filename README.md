# Untangle

AI와 나눈 대화에 흩어진 프로젝트를 한곳에 모으고, 오늘 해볼 만한 한 걸음을 초안과 함께 건네는 웹 앱입니다.

대화를 다시 읽으며 ‘어디까지 했고 다음에는 무엇을 할지’를 매번 정리해야 하는 문제를 다룹니다. AI에서 받아 온 내보내기 결과를 붙여넣으면 코드가 프로필·테마·토픽을 읽어 목록과 토픽별 보드를 만듭니다. 카드 생성 때에는 선택한 토픽과 피드백을 OpenAI에 보내 확인·선택·수정으로 시작할 수 있는 초안을 준비합니다.

## 화면 흐름

| 화면 | 사용 방법 |
|---|---|
| `/welcome` 처음 화면 | 머리줄 없이 가운데 브랜드 소개와 두 시작 버튼을 표시. ‘샘플로 둘러보기’로 두 가상 인물을 선택하거나 ‘내 기록으로 시작하기’로 `/start`에 진입 |
| `/start` | 프롬프트 복사 → ChatGPT·Claude 등에서 결과 받기 → 출처와 결과 붙여넣기 → 활성·나중에·정리 제안 확인 → ‘이대로 시작’ |
| `/` 오늘 | 가운데 열은 최대 880px. 화면 폭 1280px 이상에서는 첫 카드 왼쪽·‘다른 한 걸음’ 약 360px 열 오른쪽으로 배치하며, 그보다 좁으면 한 열로 표시. 전체 토픽 목록은 별도 화면에 표시 |
| `/topics` 현재 토픽 | 테마별 반응형 격자에서 토픽을 선택. 설명은 두 줄까지, 출처는 표시하지 않으며 별·메뉴·나중에 묶음을 각각 조작 |
| `/topics/[id]` 토픽 보드 | 제목 아래 해당 토픽의 카드, 그 아래 한 열로 ‘지금 상태·다음 할 일·막힌 점’을 표시. 나머지 정보는 ‘더 보기’로 접으며 상태·다음 할 일을 바로 편집. 카드가 없으면 버튼으로 그 토픽의 한 걸음 요청 |
| `/done` 지난 토픽 | 완료한 카드의 제목·토픽·메모를 완료 날짜별로 확인. 토픽 삭제·대화 결과 다시 가져오기 후에도 완료 당시 기록 보존 |
| 샘플 모드 | 게임 개발자·대학생의 가상 프로젝트와 저장된 카드 체험. API 호출 없이 개인 기록과 분리 |
| `/settings` 설정 | 밝기·글자 크기·움직임·하루 카드 수, 백업, 모두 지우기, 내보내기 프롬프트 다시 복사 |
| `/kit` | 카드 4종, 표·체크리스트, 버튼·토픽·테마·상태 화면의 가상 예제 |
| `POST /api/cards` | 서버 OpenAI 호출과 출력 스키마·카드 규칙 검증 |

여러 출처는 각각 보여줍니다. 겹친 항목은 확인 화면에서 직접 정리하며 자동 병합과 AI 대체 파싱은 연결하지 않았습니다.

상단의 **오늘·현재 토픽·지난 토픽** 메뉴로 이동합니다. 머리줄의 로고는 선 그림만 표시하며 접근성 이름 **Untangle 처음 화면**으로 `/welcome`에 연결합니다. `/`에 저장된 토픽이 없으면 카드 생성 없이 처음 화면으로 이동하고, 개인·샘플 토픽이 있으면 오늘 화면을 유지합니다. 카드에는 **초안**을 한 번만 표시하고 복사·고치기 아이콘을 제공합니다. **왜?**는 기본 접힘이며 펼치면 이유·행동·근거를 보여줍니다. **시작**으로 진행 중에 남기고 **다 했어요**로 완료합니다.

본문은 공식 `pretendard` 패키지 1.3.9의 400·500·600·700 굵기를 사용합니다. Instrument Serif는 오늘의 영어 제목 한 곳, 또는 처음 화면의 72px `untangle`과 기울임꼴 소개 **Every knot gives way, one thread at a time.**를 묶은 가운데 브랜드 영역에만 사용합니다. 한글 소개 **흩어진 일을 풀어, 오늘의 한 걸음으로.**와 버튼 등은 Pretendard입니다. 두 글꼴 모두 `next/font/local`로 직접 제공하며 외부 글꼴 CDN을 사용하지 않습니다. SIL OFL 1.1 원문은 [Pretendard 라이선스](public/licenses/Pretendard-LICENSE.txt)와 [Instrument Serif 라이선스](public/licenses/Instrument-Serif-LICENSE.txt)에 포함합니다.

머리줄의 톱니로 설정을 엽니다. 밝기는 기기 설정·밝게·어둡게 중 고르고, 글자는 보통 또는 전체 글자 토큰의 1.12배인 크게로 설정합니다. 움직임 줄이기는 기기 설정과 함께 적용합니다. 하루 카드 수 1·2·3장은 받은 카드 중 오늘 화면에 보여줄 개수이며 생성 입력은 바꾸지 않습니다. 모든 설정은 브라우저에 저장하며 밝기·글자·움직임은 첫 화면을 그리기 전에 적용합니다. 모두 지우기는 확인 후 Untangle의 개인·샘플 기록과 설정만 삭제합니다.

글자 토큰은 13·14·16·17·21·40px이며 초안 본문과 원문 편집은 15px입니다. 카드 등장(아래에서 8px), 나중에·관심 없어요 뒤의 카드 전환, 체크 선과 로딩 선, 토픽 상자의 2px 떠오름을 제공합니다. ‘왜?’·‘더 보기’는 지원 브라우저에서 높이를 부드럽게 전환하고 페이지 이동·밝기 변경은 짧게 화면을 겹칩니다. 일반 동작은 `--motion-fast` 또는 300ms 이하입니다. 처음 화면의 선 그림만 원본 온보딩의 엉킨 경로와 곧은 `M230 60H986` 꼬리를 2px 둥근 선으로 1200ms 동안 한 번 그립니다(엉킨 부분 65%·꼬리 35%). 기기의 움직임 줄이기 설정에서는 전환과 대기를 끄고 처음 화면도 완성된 선만 표시합니다.

선 그림 탭 아이콘, 페이지 제목·설명, 1200×630 공유 미리보기를 제공합니다. 공유 미리보기에는 앱 이름과 대표 문구만 사용하며 개인 기록은 포함하지 않습니다.

## 실행과 환경 변수

Node.js **24.x**와 npm을 사용합니다. 잠금 파일의 버전으로 설치합니다.

```powershell
npm ci
# .env.local이 없을 때만 복사합니다.
if (-not (Test-Path -LiteralPath '.env.local')) { Copy-Item -LiteralPath '.env.example' -Destination '.env.local' }
npm run dev
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다. `.env.local`이 이미 있으면 덮어쓰지 말고 필요한 값만 편집하세요. 실제 카드 생성을 사용하려면 다음 값을 설정합니다.

```dotenv
OPENAI_API_KEY=본인의_API_키
OPENAI_MODEL=gpt-5.6-terra
```

`OPENAI_MODEL`을 생략해도 기본값은 `gpt-5.6-terra`입니다. 모델을 바꿔도 프롬프트·스키마를 자동으로 바꾸지 않습니다. API 키는 서버 전용 `lib/llm.ts`에서 읽으며 `NEXT_PUBLIC_` 변수로 두지 않습니다. 온보딩 확인 화면까지는 LLM 호출이 없고 개인 모드에서 확정 후 홈에 들어가면 첫 카드를 생성합니다. 샘플 모드는 키 없이 동작합니다.

```powershell
npm run build
npm start
```

## 샘플 모드와 기록 보존

`/welcome` 또는 `/start`에서 **‘샘플로 둘러보기’**를 누르고 게임 개발자·대학생 중 하나를 고릅니다. 실제 검증에서 저장한 가상 카드 결과를 사용하며 오늘의 새 제안·토픽 보드의 명시 요청·날짜 변경·새로고침에도 실제 API를 호출하지 않습니다. 토픽 보드에서는 저장 회차 중 해당 토픽의 카드만 사용하고 다른 토픽 카드는 보존합니다. 샘플 기준일은 2026-11-12로 고정해 원래 입력·카드의 날짜 표현을 유지합니다.

상단의 **‘샘플 데이터로 보는 중’** 안내로 모드를 구분하고 **‘내 기록으로 시작하기’**로 개인 온보딩에 돌아옵니다. 샘플 변경은 `untangle.sample.workspace.v1`에, 개인 기록은 `untangle.workspace.v1`에 분리합니다. 같은 날 새로고침해도 샘플 조작이 남고, 개인 프로젝트·카드·삭제 이름 목록은 덮어쓰지 않습니다. 두 페르소나별 저장 회차와 카드 제외 근거는 `samples/card-fixtures.json`에 기록합니다.

브라우저 저장소를 지우거나 다른 브라우저·기기로 이동하면 기록이 자동으로 따라오지 않습니다. 이동 전에 아래 JSON 백업을 내려받아 새 브라우저에서 가져올 수 있습니다. 로그인·서버 동기화·서버 DB는 없습니다.

## JSON 백업

**설정 → 백업 → 내보내기**에서 현재 모드의 프로필·토픽·카드·완료 기록 등을 `untangle-날짜.json` 파일로 내려받습니다. 샘플 백업 이름에는 `sample-`이 붙습니다. 백업에는 개인 기록이 담기므로 보관할 위치를 직접 정합니다.

**가져오기**에서 이 앱으로 내보낸 JSON을 선택하면 형식·버전·자료 구조를 검증한 뒤 토픽 수와 지난 토픽 수를 보여주는 확인 창이 열립니다. **교체해서 가져오기**를 누를 때만 현재 모드의 기록을 파일 내용으로 교체합니다. 개인·샘플 백업은 같은 모드에서만 가져올 수 있고 다른 모드의 자료는 보존합니다. 취소하거나 검증·저장에 실패하면 기존 자료를 유지합니다. 백업 복원은 실제 카드 생성 요청을 만들지 않습니다.

## 토픽과 카드

- 확인 화면에서 묶음을 바꾸고 확정할 때 파싱된 자료를 저장합니다. 붙여넣은 원문은 저장하지 않습니다. 다시 가져오기 확정은 현재 토픽 목록을 교체합니다.
- 별은 최대 3개입니다. 나중에·다시 활성, 테마 이동·따로 빼기, 접힘과 선택 상태를 저장합니다. 삭제 이름 목록으로 같은 텍스트의 재등장을 막습니다. 삭제·나중에 이동은 5초 동안 되돌릴 수 있습니다.
- 보드의 ‘지금 상태’와 ‘다음 할 일’ 옆 연필로 바로 편집하고 저장합니다. 다음 할 일은 한 줄에 한 항목이며 빈 내용도 저장할 수 있습니다. 저장한 값은 다음 카드 생성 입력에 반영됩니다. 저장 실패 시 기존 값과 입력 내용을 보존하고 취소·다시 저장할 수 있습니다.
- 오늘의 카드는 온보딩 직후, 날짜가 바뀐 뒤 첫 홈, ‘새 제안 받기’에서 생성합니다. 날짜는 Asia/Seoul 기준이고 같은 날 새로고침은 저장된 결과를 사용합니다.
- 오늘 제목 옆 작은 실은 표시할 카드 묶음과 연결됩니다. 완료한 자리의 실은 곧게 펴진 상태로 새로고침 뒤에도 남습니다. 하루 카드 수를 바꿔도 받은 묶음 안에서만 표시하며 새 제안을 받으면 새 묶음으로 바뀝니다.
- 토픽 보드는 열기만 해서는 생성하지 않습니다. ‘이 토픽의 한 걸음 받기’를 누를 때 그 토픽 하나만 보냅니다. 나중에 둔 토픽도 명시 요청할 수 있으며 저장된 활성·나중에 분류는 바뀌지 않습니다. 다른 토픽 카드·오늘의 생성 기록·피드백을 보존하고 선택한 토픽의 미수락 제안만 새 결과로 바꿉니다. 진행 중 카드가 있으면 호출 없이 안내합니다.
- 오늘 카드의 입력은 활성 토픽 중 최대 9개와 최근 피드백 20건입니다. 토픽 보드의 명시 요청은 목록 순위와 활성·나중에 상태에 관계없이 하나만 고릅니다. 나중에 토픽은 오늘의 자동 선정에서는 계속 제외됩니다. 수락하고 아직 끝내지 않은 카드가 있는 토픽은 두 요청 모두에서 제외합니다.
- ‘시작’을 누르면 수락 상태를 저장하고 해당 카드의 집중 화면을 엽니다. 머리줄과 다른 카드를 숨기고 제목·편집 가능한 초안·‘먼저 이것만’·‘다 했어요’·‘나가기’를 표시합니다. Esc나 ‘나가기’로 돌아와도 진행 중 상태와 고친 초안을 유지하며 다시 집중할 수 있습니다. 완료는 기존 완료 기록에 남깁니다. 새 프로젝트는 카드를 시작할 때 토픽을 만듭니다. 48시간 지난 진행 중 카드에는 이어갈지 접을지 묻습니다.
- 완료 시 제목·토픽 이름·메모·완료 시각을 스냅샷으로 남기고 ‘지난 토픽’에서 Asia/Seoul 날짜별로 최신순 표시합니다. 토픽을 삭제하거나 대화 결과를 다시 가져와도 스냅샷은 보존합니다. JSON 백업으로 교체할 때는 백업에 담긴 완료 기록을 사용합니다.
- 카드의 ‘나중에’는 다음 날까지 숨긴 뒤 저장한 원본을 다시 보여줍니다. ‘관심 없어요’는 dismissed 피드백으로 다음 요청에 반영합니다.
- 초안은 GFM 표·체크리스트, 원문 편집·복사를 지원합니다. HTML은 실행하지 않습니다. Claude·ChatGPT로 넘기는 문구에는 고친 초안을 포함하며 복사·서비스 열기에 LLM을 호출하지 않습니다.
- 초안의 복사 옆 내려받기 아이콘은 현재 고친 Markdown 원문을 `.md` 파일로 저장합니다. 현재 토픽의 위쪽 검색은 이름과 한 줄 설명으로 바로 거릅니다. 오늘 화면 첫 방문에는 세 줄 안내를 한 번 표시하며 없는 주소에서는 선 그림과 ‘오늘로 돌아가기’를 제공합니다.
- 정상적인 빈 카드 결과는 성공입니다. 비어 있지 않은 후보가 검증에서 전부 탈락했을 때만 같은 프롬프트·스키마로 한 번 재시도합니다. SDK 자체 재시도는 꺼져 있습니다.

## 데이터와 기준 문서

`untangle_docs.zip`에서 푼 `docs/`의 여섯 파일이 기준이며 낱개 구버전은 사용하지 않습니다. 현재 제안 프롬프트는 승인된 [v0.5](docs/nudge_prompt.md)입니다. 내보내기 프롬프트·스키마·원본 분류 규칙을 임의로 바꾸지 않습니다. 디자인은 [제공 안내](docs/design_guide.md)와 [토큰](docs/tokens.css)을 따릅니다.

- `quality`는 파싱 메타데이터입니다. `{profile, themes, topics}`만 스키마로 검증하며 전체 토픽·파서 테마 수에 추가 제한을 두지 않습니다. 원본 활성 9개 사전 분류와 사용자가 바꾼 상태를 구분하고 실제 카드 요청에 보낼 토픽만 최대 9개로 고릅니다.
- 마감은 원본 JS대로 당일을 포함합니다. 지난 날짜·불분명한 일정은 원문 표현으로 보존합니다.
- 개인 기록은 localStorage에 저장합니다. 카드 생성 시 선택한 프로필·토픽·피드백은 서버를 거쳐 OpenAI에 보내며 Responses API의 `store:false`를 사용합니다. 붙여넣은 전체 원문은 보내지 않습니다. 앱 서버에 사용자 자료를 저장하거나 입력 로그로 남기지 않습니다.
- `samples/`와 샘플 카드는 가상 자료입니다. 실제 사용자 내보내기 결과는 저장소에 추가하지 않습니다.
- `.env.local`, `out/`, 결과 압축 파일, 의존성·빌드 산출물은 Git과 배포 대상에서 제외합니다. 실제 `.env.local`은 로컬에 존재하며 제외된 파일이라는 사실과 파일이 없다는 사실은 다릅니다.

## 한계

- 입력에 없는 가정 표시가 빠지거나 스케치와 구현 상태·SQL 기대 행 수를 부정확하게 표현할 수 있습니다. 중요한 사실은 초안과 입력을 대조해 확인해야 합니다.
- dismissed의 정확히 같은 action은 검증에서 버리지만, 실제 UI 검증에서 같은 토픽의 유사한 제안 방향이 다시 나왔습니다. 의미가 같은 방향까지 항상 차단하는 것은 보장하지 못합니다.
- 여러 출처 자동 겹침 찾기(`/api/dedupe`)와 AI 대체 파싱(`/api/merge`)은 미연결입니다. 프로필은 첫 결과를 사용하며 깨진 형식은 내보내기 프롬프트를 다시 복사해 시도합니다.
- 웹 검색·외부 자료 인용·AI 계정 연동·대화 자동 수집은 없습니다.
- IP당 분당 10회 호출 제한은 서버 인스턴스 메모리에만 있습니다. 여러 인스턴스에 걸친 전역 할당량 제어는 아닙니다.
- 공개 배포의 환경 변수와 실제 카드 호출 결과는 배포 환경에서 별도로 확인해야 합니다. 로컬 `.env.local`은 배포 서버에 자동으로 전달되지 않습니다.
